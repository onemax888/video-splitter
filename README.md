# 🎬 Video Clipping 视频切片工具

基于 Tauri 2、React 和 FFmpeg 的跨平台桌面视频切片工具。支持单视频选段、固定间隔切分和多视频批量处理，素材在本机处理，无需注册或激活。

本文按 `main` / `v0.2.7` 核对，更新于 2026-09-29。

![Video Clipping 界面示意](docs/screenshot.png)

> 截图来自较早版本，批量切分和精确切分选项以当前应用界面为准。

## 功能

- **时间范围切分**：手动选择多个片段，或批量粘贴时间段；支持命名、修改和预览。
- **固定间隔切分**：按秒或分钟分段，可选快速无损或按视频帧精度重编码。
- **批量视频切分**：多视频使用统一设置，支持每个视频独立文件夹或同目录连续编号、停止批次和失败项重试。
- **片头与片尾**：为每段统一添加图片或视频，图片可设置展示时长。
- **长切片加速**：时间范围模式对达到阈值的长片段使用流复制。
- **本地预览**：直接播放或使用本地 HLS 转换，支持结果预览和打开输出目录。
- **中文 / English、明暗主题**，官方分发包内置 FFmpeg 和 ffprobe。

## 单视频切分

1. 在“单视频切分”页拖入本地视频，或点击选择文件。文件选择器支持 MP4、MKV、AVI、MOV、WebM、FLV、WMV、M4V；实际兼容性取决于内部编码和文件完整性。
2. 确认时长，按需打开预览。默认模式是“时间范围”，也可切换到“固定间隔”。
3. 配置时间段或间隔、片头片尾和输出目录。单视频默认输出位置是源视频所在目录。
4. 点击“开始切分”，完成后预览结果或打开文件夹。

### 时间范围与批量录入

拖动预览进度条后点击“设为开始 / 设为结束”，也可以手动输入起止时间。支持添加多个片段、重命名和删除。

“批量录入”每行一个时间段，接受 `hh:mm:ss`、`mm:ss` 或秒数；可用 `-`、`~`、逗号或空白分隔起止时间，在末尾用 `@` 添加片段名：

```text
00:10:00 - 00:12:30@片段A
01:05:20 ~ 01:10:00@片段B
10 - 18@短片段
```

先检查解析预览，再“导入并添加”或“导入并替换”。完全重复的区间会去重；“自动合并重叠片段”默认关闭，“超出总时长自动截断”和“忽略无法解析”默认开启。

“速度 / 精度”控制起点定位方式，默认“平衡”，也可选“精确”或“快速”。普通时间范围导出会重新编码，这里的“快速”不等于固定间隔的“快速无损”。

“长切片加速”默认阈值为 20 分钟，可选关闭、10 / 20 / 30 分钟或 1 小时。片段达到阈值后使用流复制，切点可能偏离设定时间；需要精确起止位置时，应关闭长切片加速再选择精确定位。

### 固定间隔：速度与精度

| 方式 | 时间与画质 | 输出 |
| --- | --- | --- |
| 快速无损（默认） | 流复制，不重新编码；按关键帧分段，实际片长和片数可能偏离预估 | 沿用输入扩展名，排除数据轨 |
| 精确切分 | 一次整体重编码后分段，切点精确到视频帧；较慢，不能提升原始画质 | H.264 / AAC MP4，保留首个视频轨和首个音轨，不保留字幕、封面或数据轨 |

需要精确 8 秒时：关闭片头片尾，选择“固定间隔”，填入 **8 秒**，选择“精确切分”。不足一个间隔的末段会保留。例如已验证的 52.8 秒、100 fps 素材可得到 6 段 8 秒和 1 段 4.8 秒。任意帧率下并不保证文件时长显示绝对等于 8.000 秒，音频帧和封装可能带来毫秒级偏差。

### 片头片尾与输出命名

片头、片尾可独立选无、图片或视频。启用后使用重新编码的合成流程，自动禁用长切片加速，固定间隔切分方式也由程序接管。设置的间隔指正文时长；8 秒正文加 2 秒片头、1 秒片尾，最终约 11 秒。

每次单视频任务在所选目录下创建 `YYYYMMDD_HHMMSS` 子目录。文件从 `000` 开始，例如 `000.mp4`、`001.mp4`；命名后可为 `000_片段A.mp4`。固定间隔精确模式输出 MP4；其他现有导出路径沿用输入扩展名，重新编码时仍可能遇到编码与容器不兼容的问题。

## 批量视频切分

切换到“批量切分”，一次选择或拖入多个视频。同次导入按文件名自然排序（video2 在 video10 前），新文件追加到队尾；可上移、下移、移除或清空。相同路径会去重，不同目录的同名视频可以同时处理。

统一设置固定间隔、快速无损 / 精确切分、片头片尾和输出目录。默认间隔为 8 秒，默认每个视频一个文件夹。当前批量模式只支持固定间隔；逐视频编辑任意时间范围使用单视频模式。

每次批次创建独立时间戳目录，输出布局可选：

- **每个视频一个文件夹**：`001_视频A/000001.mp4`、`002_视频B/000001.mp4`，各视频从 1 开始编号。
- **全部视频一个文件夹**：`000001.mp4`、`000002.mp4`，按视频队列与片段时间顺序，依据实际成功输出数连续编号。

编号至少补齐 6 位；同一视频的输出按所需位数统一扩宽，不回改之前视频的文件名。快速无损沿用输入扩展名；未启用片头片尾的精确切分输出 MP4。`切分清单.csv` 记录素材路径、输出路径、序号以及失败 / 停止状态。

视频逐个处理，当前视频全部成功后才发布其输出。一般素材错误会记录并继续；磁盘空间不足、输出写入失败等问题会停止批次。点击“停止批次”会终止当前 FFmpeg 进程并清理该视频未完成的文件，已成功结果保留。

“将失败项作为新批次重试”使用当前设置创建新目录。停止时未处理的视频仍在队列中，可整理队列后重新开始；关闭程序后的自动续跑暂不支持。

## 常见问题

**为什么按 8 秒切分，最后只有一段？**

快速无损依赖关键帧，关键帧稀疏时无法按预期分段。改用精确切分；若有明确错误提示，再检查素材与输出目录。`v0.2.6` 已修复部分相机数据轨导致的固定间隔失败，以及失败后遗留文件被误判成功的问题。

**所有模式都无损、都很快吗？**

只有流复制不重新编码。精确切分、普通时间范围导出和片头片尾合成会转码，耗时取决于分辨率、帧率、编码、磁盘和设备；重新编码也可能产生画质损失。

**进度长时间不动是否卡住？**

进度主要按片段或视频完成情况更新，单次转码中可能长时间保持初始值。结合任务耗时、错误提示与素材规模判断，不要仅凭进度百分比判断失败。

**预览打不开是否代表不能导出？**

不一定。预览受系统 WebView 的解码能力影响；大文件或部分格式会转成本地 HLS，首次播放或远距离跳转可能需要等待并占用临时磁盘空间。可用本地播放器检查最终输出。

**检测不到 FFmpeg，设置 PATH 能解决吗？**

应用使用内置 sidecar，单独改 PATH 不会补回缺失组件。请重新安装完整分发包；源码开发时检查 `src-tauri/binaries/` 中是否有目标平台的 ffmpeg 和 ffprobe，Unix 系统还需执行权限。

**支持在线下载、字幕转录或 AI 高光识别吗？**

当前 `main` 的正式功能面向本地视频。`online_download_support` 是独立实验分支，其在线下载与转录相关实现不等于普通分发包已支持；AI 高光识别等后续想法不属于当前功能承诺。

## 开发与构建

需要 Git、**Node.js 20.19+（20 系列）或 22.12+**、当前稳定版 Rust，以及对应平台的 Tauri 2 系统构建依赖。推荐 Node.js 22 LTS。项目使用 React 19、TypeScript 5.8、Vite 7、Tailwind CSS 3 和 Tauri 2。

- macOS：Xcode Command Line Tools。
- Windows：Visual Studio C++ 构建工具和 WebView2。
- Linux：WebKitGTK 4.1、AppIndicator、librsvg、patchelf 等；Ubuntu 依赖列表见 [发布工作流](.github/workflows/release.yml)。

```sh
git clone https://github.com/qindongliang/video-splitter.git
cd video-splitter
npm ci

# 桌面开发模式
npm run tauri dev

# 类型检查及前端生产构建
npm run build

# 本机平台的生产安装包
npm run tauri build

# Rust 单元测试
cargo test --manifest-path src-tauri/Cargo.toml

# 真实 FFmpeg 切分、解码与中断测试
cargo test --manifest-path src-tauri/Cargo.toml -- --ignored
```

仓库包含四种目标平台的 FFmpeg / ffprobe 二进制，文件名附带 Rust target triple。构建其他目标时需相应工具链及平台环境；`npm run tauri build` 不会在一台电脑上自动构建全部平台。项目未配置 `npm run lint`。

主要目录：`src/components/` 为界面组件，`src/hooks/` 为切分与预览逻辑，`src/i18n/` 为中英文文案；`src-tauri/src/ffmpeg.rs` 为媒体处理，`batch.rs` 为批次调度与输出，`process.rs` 为可停止的子进程管理。

## 发布流程

[Build and Release](.github/workflows/release.yml) 由 **推送 `v*` 标签**或手动 `workflow_dispatch` 触发；仅推送 `main` 不会触发此工作流。

1. 同步修改 `package.json`、`package-lock.json`、`src-tauri/Cargo.toml`、`src-tauri/Cargo.lock` 和 `src-tauri/tauri.conf.json` 的应用版本。
2. 完成对应验证，提交并推送 `main`，再对目标提交创建、推送新版本标签。
3. 标签触发 macOS Apple 芯片、macOS Intel、Windows x64、Linux x86_64 构建，产物写入 **Release 草稿**，不会自动公开发布。
4. 检查安装包与发布说明后，再决定是否发布草稿。

手动构建可以选择平台；当前工作流只有手动选择 Windows 且不在标签上时会上传可下载的 Actions artifact，其他非标签手动构建主要用于验证。不能将手动构建成功视为已创建 Release。
